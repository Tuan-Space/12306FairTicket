# 四步订票流程操作说明

**① 设置行程 → ② 登录并选择乘车人 → ③ 确认并开始 → ④ 等待结果**

首次准备时，前三页显示“任务未开始”。扫码登录、选择乘车人和校准时间都是准备操作；确认页点击“开始任务”才会执行，停止后点击“继续任务”会重新创建一轮任务。窗口默认大小为 750×880 逻辑像素，并根据屏幕可用空间调整；顶部步骤和底部操作保持可见，正文可以滚动。第 ④ 页的详细日志固定在窗口底部，默认展开，可随时收起。

## ① 设置行程

先设置购物车共用的乘车日期、开售时间与停止时间。在“添加备选”区域选择出发站、到达站、车次范围和一种席别，然后点击 **“加入购物车”**。新打开程序购物车为空，不预选席别。

- 指定多个车次（例如 `G103，G105`）会按填写顺序拆成多行，每行只有一个车次、一种席别；支持中英文逗号、顿号、分号、换行和制表符。
- “不限车次”须明确选择，表示接受这一站对的所有车次，但只接受本行席别。指定车次留空不会自动扩大范围。
- 同一车次的二等座、一等座分别加入；北京南—上海虹桥与北京—上海等不同站对可以交错排序。
- 完全相同的项目不重复加入，已有顺序保持。加入后保留输入，方便只修改一项再添加。
- 点顶部固定的 **“购物车（N）”** 打开排序面板：可拖动、上移、下移、编辑或删除。键盘 `Alt+↑/↓` 调整顺序，`Enter` 编辑，`Delete` 删除。编辑区保存只改当前一行；面板“完成”才提交整个列表，“取消”放弃面板内的更改。
- 未加入的输入不会参与抢票。点击下一步遇到未处理更改时，选择“加入并继续”“仅使用购物车”或“返回编辑”。空购物车不能进入下一步。

**从上到下就是实际尝试顺序。** 例如“北京南 G103 二等座 → 北京 1461 硬卧 → 北京南 G103 一等座”，实际也按此顺序；同站对的多个项目仅复用本轮查询结果。不限车次项目内部按车次编号排序，重叠命中的同车、同区间、同席别每轮只尝试一次。

所有项目是一次出行的备选，共用乘车人和日期；不是分别购买多段行程。任意一项成功，整车停止。所有站对共享查询限速；站对越多，一轮查询可能越久。查询失败会与成功但无票分别显示，失败站对下一轮重试。“最大查询轮数”按完整购物车轮询计数。

选择自动提交或仅监控；仅监控不提交订单。高级参数默认折叠。顶部“保存为…”保存购物车与公共参数，不保存添加区尚未加入的内容；“导入…”恢复保存的选择。点击 **“下一步：登录与乘车人”**，问题会定位到对应字段。

## ② 登录与乘车人

未登录时，在账号区域点击 **“扫码登录 12306”**，用 12306 App 扫码并在手机上确认。本页会显示二维码有效期；过期后可刷新。底部可以返回上一步，登录成功后显示“下一步：确认任务”；扫码入口与步骤导航分开。

登录成功后，页面显示已登录，并在同一区域加载联系人。直接勾选乘车人，最多 5 人，按勾选先后保留顺序。每个人可选择默认、成人票或学生票；默认按 12306 乘客信息购买。尚未确认联系人类型时显示“默认（按12306乘客信息）”，已读取成人或学生身份时分别显示“默认（12306：成人票）”或“默认（12306：学生票）”。学生联系人可以购买成人票；非学生联系人不能仅通过切换车票类型获得学生资格，实际资格仍由 12306 审核。

也可以使用手动填写姓名入口。多个姓名支持英文或中文逗号、顿号、英文或中文分号、换行和制表符；姓名必须与账号中的联系人完全一致。重复姓名和同名联系人歧义会明确提示，不会默选其中一人。

联系人读取失败时，**已登录状态会保留**。可点击“重新读取”，或手动填写姓名。“重新读取”只读取数据，不会触发订票；若会话已失效，页面会提示回到扫码登录状态。

选人完成后，核对显示的人数与车票类型，点击 **“下一步：确认任务”**。此时仍未开始查票或下单。

准备页没有单独的“检查登录状态”按钮，直接登录即可；等待开售期间可在运行页检查会话。检查结果带有时间，网络错误会显示“检查失败”，不会等同于登录失效。

## ③ 确认任务

按顺序核对购物车全部项目，并核对公共日期、开售时间、乘车人、车票类型和任务模式。发现问题可返回前面的步骤修改，草稿会保留。

人数确定后，可在本页设置座位关系、上中下铺数量及静音车厢偏好：

- 座位、铺位偏好只作用于适用席别；购物车删除所有对应席别后，已填偏好会保留为“未启用”，重新选择该席别后恢复校验。
- 启用的座位或铺位数量需要与乘车人数一致，返回修改人数后请重新核对。
- 静音偏好默认关闭，仅在二等座订单且服务端明确支持时尝试；全部同行乘车人均须遵守静音要求。
- 位置和静音均是偏好，不保证分配成功；程序不会为换位置或车厢自动取消重订。

点击 **“开始任务”** 后，程序执行完整检查并进入第 ④ 页。确认页已承担最终确认作用，不再重复弹出同一份摘要。若存在错误，会返回错误所属页面和字段。

## ④ 等待结果

运行页显示当前备选的编号、实际站对、车次和席别。买到票后明确显示成功区间。运行页显示任务真实状态：正在准备、等待开售、查票中、提交中、排队中及最终结果。大号倒计时、查询指标和运行时间线只在此处显示。详细日志继续显示在窗口底部，错误摘要和结果保持可见。

| 页面状态 | 接下来怎么做 |
| --- | --- |
| 等待开售、查票中或提交中 | 保持程序运行，按需查看详细日志。 |
| 当前任务等待重新登录，扫码后自动继续 | 在本页扫描恢复二维码并确认；无需再点击“开始任务”。二维码过期可刷新，也可停止。 |
| 任务已停止 | 需要修改时返回确认页；无需修改时可点击“继续任务”，从 0 开始新一轮查询。 |
| 订单成功 | 点击“前往 12306 支付”，在官方 App 或官网核对待支付订单并完成支付。 |
| 订单状态无法确认 | 先到官方订单页核对，避免直接重复提交。 |

“停止任务”会取消后续操作，但可能需要等待当前网络请求结束。第 ④ 页点击“上一步”也会立即请求停止，并返回第 ③ 页；在当前请求结束及后台清理完成前，页面显示停止过程，参数保持只读。停止完成后即可修改，重新执行仍须明确点击“开始任务”。

运行中“查看本轮购物车”只读。结果页的“继续任务”使用上一轮完整购物车快照重新创建任务，查询计数从 0 开始，不会从旧查询轮次或旧候选继续。仍有效的会话和上次成功的校时结果可以复用。乘车日期或原停止时间已经过去时需要先修改配置，跨午夜也不会把原停止时间自动顺延到下一天。若订单状态无法确认，应先到 12306 核对，不能把“继续任务”当作确认旧订单是否成功的方式。

程序不会弹出 Windows 系统通知或播放声音，请留意程序窗口。

## 辅助操作与自动维护

“校准时间”位于时间设置和运行页的辅助区域，显示 RTT、时钟偏移和校准时间。空闲与等待时可用，登录、查票和下单时停用；校时或检查执行中会防止重复操作。校时失败保留上次成功结果，准备时校时不会开始任务。

定时任务通常在开售前 3 分钟复查登录、前 1 分钟最终校时；已有热身安排、较晚登录时的补校时和长热身边界规则保持不变。等待中明确发现登录失效时，任务暂停并要求重新扫码；扫码成功后重新匹配乘车人，继续原任务。手动检查遇到网络错误时会保留原等待状态；自动复查失败则结束任务并说明原因。

## 配置与本地数据

保存使用 **JSON version 5**，继续读取 v1–v4。旧配置会展开成可见的购物车项目：明确车次按旧策略排列，允许其他车次时增加“不限车次”备选。旧“车次优先 + 不限车次 + 多个席别”无法完全保持原顺序，会在购物车和确认页持续提示顺序变化；请自行核对调整。

旧配置仅限高铁/动车、普通列车等新界面无法表达的限制会保留为待修正状态，不能启动。请编辑为明确车次，或明确接受目前显示的不限车次范围，再点击“确认按当前购物车范围执行”。仅添加、排序或保存不会自动消除这项限制。无效的空指定车次配置同样需修正。

配置只保存可编辑参数，不保存向导进度、登录状态、Cookie、二维码、Token、证件号码或手机号。每次重新打开程序均需重新登录；同次运行可复用仍有效的会话。

应用版本为 **2.0.0**。CLI 可设置 `CART_ITEMS` 使用相同购物车流程；省略时继续使用旧车次、席别与策略参数。Windows 便携版使用时必须保留 EXE 旁的整个 `_internal` 文件夹。
