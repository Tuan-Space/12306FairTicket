# 四步订票流程操作说明

**① 设置行程 → ② 登录并选择乘车人 → ③ 确认并开始 → ④ 等待结果**

前三页都是准备步骤。扫码登录和选择乘车人不会启动任务；确认页点击“开始任务”才会执行，停止后点击“继续任务”会重新创建一轮任务。窗口默认大小为 750×880 逻辑像素，并根据屏幕可用空间调整；顶部步骤和底部操作保持可见，正文可以滚动。第 ①–③ 页右下角常驻圆形购物车图标，右上角数字是已加入的备选数量。第 ④ 页日志固定在窗口底部，默认约三行，内容可单独滚动，筛选与操作按钮直接显示在同一行。

## ① 设置行程

先设置购物车共用的乘车日期、开售时间与停止时间。点击日期框任意位置可以打开日历；开售时间和停止时间并排显示，可选“立即开始”或“不设停止时间”。程序启动任务后会自动校时，第一步不需要手动校时。

在“添加备选”区域选择出发站、到达站、车次范围，并勾选席别。出发站、到达站与更新站点按钮在同一行，车次范围与指定车次输入也在同一行。“坐席”“卧铺”两个菜单默认展开，每行三个选项，共十二种席别，可以多选。新打开程序购物车为空，不预选席别。

- 指定车次支持中英文逗号、顿号、分号、换行和制表符，按填写顺序保留。
- 席别按勾选顺序编号；取消后重新勾选排到末尾。整项点击或按空格可以切换。
- 同时选择多个车次和席别时，先按席别勾选顺序，再按车次填写顺序生成所有组合。填写 `G103、G105`，先勾二等座、再勾一等座，会生成 **G103 二等座 → G105 二等座 → G103 一等座 → G105 一等座**。
- “不限车次”须明确选择，表示接受这一站对的所有车次；每种已选席别各生成一行。指定车次留空不会自动扩大范围。
- **“加入购物车”按钮显示本次新增条数**，已经存在的完全相同项目不计入新增数。需要核对搭配时，点旁边的预览入口查看完整组合；预览不会加入或开始任务。每个备选只有一个车次或“不限车次”，以及一种席别。北京南—上海虹桥与北京—上海等不同站对可以交错排序。
- 完全相同的项目不重复加入，已有顺序保持。加入后保留输入，方便只修改一项再添加。

**注意多选会生成全部组合。** 如果填写 G103、D17，同时勾选二等座、二等卧，会生成四行。若只接受 **G103 二等座** 和 **D17 二等卧**，请分别添加，或删除另外两行；程序不会根据车次前缀替你猜测哪些组合可以接受。

点第 ①–③ 页右下角的 **圆形购物车图标**，打开居中面板。每个备选用单行显示顺序号、站对、车次与席别；较长内容省略显示，悬停可看完整内容。拖动**行右侧的手柄**可以排序，也可上移、下移、编辑或删除。键盘 `Alt+↑/↓` 调整顺序，`Enter` 编辑，`Delete` 删除；图标本身也可用 Tab 聚焦、空格或回车打开。编辑区保存只改当前一行；面板 **“保存修改”** 才提交整个列表，“取消”放弃面板内的更改。第二、三页保存修改后，摘要和偏好适用项目也会更新；清空购物车后，需要回到第一步添加，才能开始任务。后台操作执行期间面板只读。

未加入的输入不会参与抢票。点击下一步时，会具体询问是否将当前站对、车次与席别加入购物车，并列出数量；可选“加入并继续”“不加入，继续下一步”或“返回修改”。填写不完整时会指出需要补充的内容。空购物车不能进入下一步。

**从上到下就是实际尝试顺序。** 例如“北京南 G103 二等座 → 北京 1461 硬卧 → 北京南 G103 一等座”，实际也按此顺序；同站对的多个项目仅复用本轮查询结果。不限车次项目内部按车次编号排序，重叠命中的同车、同区间、同席别每轮只尝试一次。

所有项目是一次出行的备选，共用乘车人和日期；不是分别购买多段行程。任意一项成功，整车停止。所有站对共享查询限速；站对越多，一轮查询可能越久。查询失败会与成功但无票分别显示，失败站对下一轮重试。“最大查询轮数”按完整购物车轮询计数。

选择自动提交或仅监控；仅监控不提交订单。高级参数默认折叠，每行三个，数字框不响应鼠标滚轮改值，仍可直接输入或用键盘调整。顶部“保存为…”保存购物车与公共参数，不保存添加区尚未加入的内容；“导入…”恢复保存的选择。点击 **“下一步：登录与乘车人”**，问题会定位到对应字段。

## ② 登录与乘车人

未登录时，在账号区域点击 **“扫码登录 12306”**，用 12306 App 扫码并在手机上确认。本页会显示二维码有效期；过期后可刷新。底部可以返回上一步，登录成功后显示“下一步：确认任务”；扫码入口与步骤导航分开。

登录成功后，页面显示已登录，并加载三列联系人，人数合并在“乘车人（N/5）”标题中。直接点击整项或按空格勾选，最多 5 人，按勾选先后保留顺序。刷新联系人按钮位于首行右侧。长姓名在单元内省略显示，悬停可见全名，选择和提交仍使用完整姓名。

每人的车票类型同样按每行三列排列，姓名在上、下拉框在下。尚未确认联系人类型时显示“12306默认”，已读取成人或学生身份时分别显示“12306默认（成人）”或“12306默认（学生）”；悬停可查看完整含义。每人都可单独选择默认、成人票或学生票。学生联系人可以购买成人票；非学生联系人不能仅通过切换车票类型获得学生资格，实际资格仍由 12306 审核。尚未选择或填写姓名时，不显示空的票种编辑区。

“乘车人”标签和姓名输入框在同一行，进入本页即显示，无需展开。勾选联系人会按顺序回填，直接修改姓名也会同步联系人和购票类型。后台操作期间输入框仍可见，但暂时不能编辑。多个姓名支持英文或中文逗号、顿号、英文或中文分号、换行和制表符；姓名必须与账号中的联系人完全一致。重复姓名和同名联系人歧义会明确提示，不会默选其中一人。

联系人读取失败时，**已登录状态会保留**。可点击“重新读取”，或手动填写姓名。“重新读取”只读取数据，不会触发订票；若会话已失效，页面会提示回到扫码登录状态。

选人完成后，核对显示的人数与车票类型，点击 **“下一步：确认任务”**。此时仍未开始查票或下单。

准备页没有单独的“检查登录状态”按钮，直接登录即可；等待开售期间可在运行页检查会话。检查结果带有时间，网络错误会显示“检查失败”，不会等同于登录失效。

## ③ 确认任务

页面以紧凑清单呈现购物车全部项目，以及公共日期、开售时间、乘车人、车票类型和任务模式。按顺序核对后再开始；发现问题可返回前面的步骤修改，草稿会保留。导入配置或修改购物车后，清单会同步更新。

人数确定后，可在本页设置座位关系、上中下铺数量及静音车厢偏好。页签标出适用备选数量，座位图的操作说明直接显示。切换座位、铺位页签时，高度随当前内容调整。

- 例如，第 1 项 G103 二等座使用座位偏好，第 2 项 D17 二等卧使用铺位偏好。**位置偏好不能改变项目的车次、区间或席别**，二等座不会因上铺偏好变成卧铺，二等卧也不会因靠窗偏好变成座席。
- 座位、铺位偏好只作用于适用席别；购物车删除所有对应席别后，已填偏好会保留为“未启用”，重新加入该席别后恢复校验。
- 启用的座位或铺位数量需要与乘车人数一致，返回修改人数后请重新核对。
- 静音偏好默认关闭，仅在二等座订单且服务端明确支持时尝试；全部同行乘车人均须遵守静音要求。
- 位置和静音均是偏好，不保证分配成功。服务端未开放选座、选铺或中铺时，会在当前项目指定的席别内由系统分配并提示；不会换成其他席别，也不会为换位置或车厢自动取消重订。

点击 **“开始任务”** 后，程序执行完整检查并进入第 ④ 页。确认页已承担最终确认作用，不再重复弹出同一份摘要。若存在错误，会返回错误所属页面和字段。

## ④ 等待结果

运行页集中显示一处真实任务状态：正在准备、等待开售、查票中、提交中、排队中及最终结果，同时显示当前备选的编号、实际站对、车次和席别。倒计时仅在等待开售时显示；结束后不再显示“正在准备”或零倒计时。已尝试的备选可作为最后尝试信息保留，买到票后明确显示成功区间。

“查询轮数”“RTT”“时钟偏移”三个指标框同排显示数值，不能点击。未校时时后两项显示 `--`；重校失败保留上次成功数值，并直接提示失败。登录检查、校时结果和检查时间直接展示。

“查看购物车”“检查登录状态”“校准时间”三个辅助按钮排列在同一行。日志固定在正文下方、操作栏上方，默认约三行，小窗口约两行，内容单独滚动；工具栏同排提供“详细日志”、级别筛选、暂停滚动、清空、复制和导出。点击“详细日志”可收起正文，按钮仍可使用。错误原因和订单结果始终在主界面可见，不需要翻日志寻找。

| 页面状态 | 接下来怎么做 |
| --- | --- |
| 等待开售、查票中或提交中 | 保持程序运行，按需查看详细日志。 |
| 当前任务等待重新登录，扫码后自动继续 | 在本页扫描恢复二维码并确认；无需再点击“开始任务”。二维码过期可刷新，也可停止。 |
| 任务已停止 | 需要修改时返回确认页；无需修改时可点击“继续任务”，从 0 开始新一轮查询。 |
| 任务结束，未出票 | 已到停止时间或查询上限；需要再次尝试时，返回修改配置并重新开始。 |
| 订单成功 | 点击“前往 12306 支付”，在官方 App 或官网核对待支付订单并完成支付。 |
| 订单状态无法确认 | 显示待核对结果，先到官方订单页核对；不能当作未出票直接重试。 |

“停止任务”会取消后续操作，但可能需要等待当前网络请求结束。第 ④ 页点击“上一步”也会立即请求停止，并返回第 ③ 页；在当前请求结束及后台清理完成前，页面显示停止过程，参数保持只读。停止完成后即可修改，重新执行仍须明确点击“开始任务”。

运行中“查看本轮购物车”只读。结果页的“继续任务”使用上一轮完整购物车快照重新创建任务，查询计数从 0 开始，不会从旧查询轮次或旧候选继续。仍有效的会话和上次成功的校时结果可以复用。乘车日期或原停止时间已经过去时需要先修改配置，跨午夜也不会把原停止时间自动顺延到下一天。若订单状态无法确认，应先到 12306 核对，不能把“继续任务”当作确认旧订单是否成功的方式。

程序不会弹出 Windows 系统通知或播放声音，请留意程序窗口。

## 辅助操作与自动维护

第一步没有手动校时按钮。任务启动时会自动校时；第 ④ 页辅助操作保留“校准时间”，可查看 RTT、时钟偏移和校准时间。允许辅助操作的空闲或等待状态下可用，登录、查票和下单时停用；校时或检查执行中会防止重复操作。校时失败保留上次成功结果。后台操作开始、结束不应改变正文的阅读位置，主动切换页面或定位错误时才滚动。

定时任务通常在开售前 3 分钟复查登录、前 1 分钟最终校时；已有热身安排、较晚登录时的补校时和长热身边界规则保持不变。等待中明确发现登录失效时，任务暂停并要求重新扫码；扫码成功后重新匹配乘车人，继续原任务。手动检查遇到网络错误时会保留原等待状态；自动复查失败则结束任务并说明原因。

## 配置与本地数据

保存与导入仅支持 **JSON version 5**。旧 v1–v4 配置不能导入，请重新建立购物车；带有未解决历史范围限制的 v5 也会拒绝导入，避免无意扩大购票范围。普通 v5 配置可继续使用。

配置只保存可编辑参数，不保存向导进度、登录状态、Cookie、二维码、Token、证件号码或手机号。每次重新打开程序均需重新登录；同次运行可复用仍有效的会话。

应用版本为 **2.1.0**。CLI 必须填写 `CART_ITEMS`，使用相同购物车流程；具体参数见源码中的 `config.py`。Windows 便携版完整解压后运行 `12306FairTicket.exe`，保留旁边整个 `_internal` 文件夹。
