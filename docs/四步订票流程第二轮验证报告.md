# 四步订票流程第二轮验证报告

日期：2026-09-28。应用版本保持 **1.1.1**。本报告对应四步流程的第二轮交互调整，源码与构建产物仅交付本地，不包含 GitHub 发布。

## 调整范围

- 扫码入口放回第 ② 页账号区域，底部保留步骤导航；准备阶段不再显示登录检查按钮。
- 乘车人字段统一称为“车票类型”。默认项说明按 12306 乘客信息购买；已读取的成人或学生类型直接显示在默认项及确认摘要中，保存值与后端规则不变。
- 运行页停止后可以继续任务；继续会创建新一轮任务，查询计数从 0 开始。第 ④ 页返回时立即请求停止，在后台收尾完成前保持配置只读。
- 第 ④ 页的详细日志固定在窗口底部，默认展开；默认窗口为 750×880 逻辑像素，并适配屏幕可用区域。
- 后台操作复用窗口生命周期内的工作线程和工作对象，每轮使用独立参数、取消令牌和代次。关闭时先把工作对象移回 GUI 线程，确认后台退出后才销毁并释放会话；GUI 不执行阻塞式线程等待。
- 联系人列表复用现有 Qt 控件。相同联系人数据不重建列表，空列表与重复失效事件使用固定提示控件，清空时隐藏已有选项，避免反复销毁和创建。

## 结果记录

测试环境：Windows、Python 3.12.12、PySide6 / Qt 6.8.3。测试记录放在 `artifacts/`，Windows 包会附最终日志。

- 完整模拟回归：**885 passed，13 subtests passed**（`artifacts/wizard-r2-final-full.txt`）。
- 150%／200% GUI 回归：分别 **319 passed**（`artifacts/wizard-r2-final-scale-1.5.txt`、`artifacts/wizard-r2-final-scale-2.txt`）。
- 最终关闭协议压力测试：50 次真实窗口与常驻执行器的启动／关闭，包含操作中取消关闭和完成后关闭；所有执行器原生销毁均在 GUI 线程。1,953 次心跳，最大间隔 47ms，2 项测试通过（`artifacts/wizard-r2-final-stress.txt`）。
- 常驻工作对象重复操作：200% 下三个独立进程各 10 项通过，包含累计 600 次未登录检查、代次隔离、联系人空列表刷新和 GUI 心跳。
- 对象回收压力测试：故意遗留 15 个已关闭窗口的 Python 包装器环，在后台触发 5,021 次 GC（4,557 次发生在后台）；GUI 6,697 次心跳，最大间隔 16ms，无挂起。
- 代码审查补充修正：延迟文本日志不再推进任务状态；格式异常的确认排队和出票查询回执保持订单未知状态，不允许重试下单。
- 原生显示：检查深浅主题、100%／150%／200% 缩放；屏幕不足时缩小窗口，在极短窗口压缩页头和留白。详细日志正文独立滚动，步骤及底部操作不随正文滚动。

### 偶发卡死排查记录

最初模拟未登录检查时，界面创建联系人提示与临时工作对象销毁重叠；本轮改为常驻线程和复用提示。扩展压力回归仍捕获过关闭时的 native 挂起：GUI 正在创建 Qt 事件循环，后台线程正在收尾。最终退出协议将工作对象先迁回 GUI 线程，避免后台原生销毁 Python Qt 对象与 GUI 创建操作交错。

另发现未设置 parent 的旧登录检查按钮和日志信号对象。两者已绑定窗口生命周期，消除孤立按钮通过信号持有窗口的泄漏路径。不能据此声称已证明最初用户环境中卡死的唯一原生锁原因；以下最终验证记录的是修正后可复现路径与压力测试结果。
