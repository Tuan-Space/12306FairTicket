# 四步订票流程验证报告

日期：2026-09-28。源码目录：`F:\research_project\12306`。应用版本保持 **1.1.1**。

本轮将 GUI 改为“设置行程 → 登录与乘车人 → 确认任务 → 等待结果”四个分步页面。源码和构建产物仅保留本地；未推送 GitHub、创建标签或发布 Release。此前 [本地功能改进验证报告](本地功能改进验证报告.md) 记录的是四步改版前的功能与包，不代表本轮界面。

## 已实现的流程

- 前三页持续显示“任务未开始”，顶部步骤条和底部操作固定可见。登录、读联系人、检查会话和校时均不会启动订票；只有确认页的“开始任务”创建任务，重复点击不会重复创建。
- 第 ① 页设置行程、时间、车次范围、席别顺序和任务模式，高级参数默认折叠。取消了原先 1200 像素固定最小宽度；正文可滚动。
- 第 ② 页使用统一扫码入口；成功后在本页读取并勾选联系人，支持逐人票种和手填姓名。读取联系人失败保留已登录状态，提供重试和手填入口。刷新联系人不会隐式生成二维码。
- 第 ③ 页显示最终摘要，并设置座位、铺位和静音偏好；替代原有启动确认弹窗。每次下一步只校验当前页面，开始前完整校验，错误定位到所属页面。
- 第 ④ 页显示真实运行阶段和结果。会话失效时原地展开恢复二维码，扫码后恢复同一任务；停止完成后通过“修改配置”保留草稿、会话和校时结果，再次启动仍需确认。
- 详细日志默认折叠，错误与结果保持可见；系统通知和声音仍关闭。JSON 保持 version 4，不保存步骤进度或登录状态，CLI 与订票策略保持不变。

## 重点回归

| 场景 | 验证内容 |
| --- | --- |
| 首次使用与分步校验 | 初始零席别、空偏好；下一步不验证未来页面字段；确认页外不能启动 |
| 登录与联系人 | 登录后自动读取且不启动；读取失败与认证失败分开；刷新只读；最多五人、选择顺序、重名和学生身份限制 |
| 返回与导入 | 返回修改保留草稿，人数／席别改变后重新检查偏好；v4 导入不会登录或启动；旧配置兼容继续回归 |
| 监控模式 | 允许不选择乘车人，仍通过明确的登录与确认步骤开始，不提交订单 |
| 停止与恢复 | 取消独立操作保持任务未开始；等待时二维码恢复不重建任务；停止修改重启复用进程内会话 |
| 旧结果隔离 | 操作代次拒绝旧回调；取消后晚返回联系人不回填；延迟查询显示不能覆盖停止、失败或成功状态 |
| 线程收尾 | 主线程接收明确的 Qt 槽；工作线程结束后等待原生清理完成，再释放引用、复用会话或关闭程序 |
| 键盘与布局 | 空格选择联系人、逐步前进；深浅主题与多种模拟缩放；确认摘要可滚动到最后一行 |

线程退出使用 `finished → worker.deleteLater`，GUI 收到结束信号后通过 `wait()` 确认线程清理完成，再允许下一次操作。关闭窗口也遵守相同边界。Qt 文档说明，结束信号可能早于线程本地析构；Windows 上 `wait()` 成功才确认操作系统线程退出。[Qt QThread 文档](https://doc.qt.io/qt-6/qthread.html)

测试中复现并修复了以下问题：普通登录复查误显示恢复扫码引导、缓存的查询事件覆盖终态、后台对象清理与下一轮 UI 回调交错，以及关闭窗口绕过线程收尾。使用明确的代次和主线程接收对象，不访问已销毁的 Qt sender，也不在析构中增加 Python 销毁监听。
