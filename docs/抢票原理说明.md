# 程序运行原理

GUI 与 CLI 共用一套订票流程。GUI 负责四步准备、交互和状态展示；查票与下单由 `TicketRunner` 执行。

## 入口与配置

- `gui.py` → `ticket_app/gui/app.py`：创建窗口。`wizard.py` 管理四步导航；`compat.py` 读写 JSON v4、迁移旧配置并加载内置站点快照；`validation.py` 检查各步骤字段。
- `main.py`：加载指定的 Python 配置，或仅执行 `--validate-config`。GUI 不会执行导入的 Python 脚本。
- `configuration.py`：形成 `AppConfig`，检查日期、乘车人、席别、策略与时间。`input_parsing.py` 统一处理多个分隔符。

## 准备阶段不订票

GUI 第二步扫码登录并读取联系人；选择成人／学生票与联系人本身的类型分开保存。`passengers.py` 负责姓名匹配、重名歧义和票种校验；`passenger_widgets.py` 只接收显示所需的姓名与类型，不把证件信息写入配置。

确认页点击开始后才创建订票任务。窗口保有单个后台线程和工作对象，串行处理登录、联系人、校时和任务；每次操作携带独立参数、取消令牌与代次。旧请求的迟到结果不能覆盖下一次操作。退出时异步等待收尾，再按 Qt 对象所属线程释放资源。

## 定时等待与登录维护

`clock.py` 采样服务器时间，采用可用的低 RTT 样本修正单调时钟。通常在开售前 3 分钟复查登录、前 1 分钟最终校时，之后按配置提前热身查询。较晚登录会补校时；较长热身时点会把两次维护相应前移。

明确失效时暂停并请求重新扫码，成功后重新匹配乘车人再继续原定目标。手动检查的网络／响应错误只表示检查失败，不等同失效。查票与下单期间不额外增加逐候选登录检查。

## 查询与候选顺序

`stations.py` 获取站点编码，GUI 另有随源码提供的 `assets/stations_snapshot.json` 用于离线字段校验。`client.py` 解析余票响应，保留实际席别代码；一等卧 `I`、二等卧 `J` 与共享显示列的软卧 `4`、硬卧 `3` 分开处理。无法区分时跳过相应卧铺候选。

`train_policy.py` 集中处理车次范围、类型及候选顺序：

- **车次优先**：先按车次顺序，再按席别顺序。
- **席别优先**：先对全部允许车次尝试首选席别，再尝试下一席别。

实际运行跳过无票候选。GUI 未填车次时不限类型；填了车次且勾选「只尝试上述车次」时严格限定清单。仅监控模式不调用下单流程。

## 提交、偏好与订单安全

`client.py` 与 `runner.py` 沿共享订单流程准备确认页、校验订单、读取服务端能力、提交确认并等待订单结果。网页中的对象以 JSON／JSON5 解析，不执行 JavaScript。`preferences.py` 和 `quiet_capability.py` 根据实际席别、返回的座位／铺位布局及静音能力决定本候选可以提交哪些偏好；不能满足时按既定规则降级，不为换位置取消重订。

本次购买的票种与原联系人类型分别形成订单和联系人提交字符串。学生资格被服务端拒绝时提示用户修改，不自动改成成人票购买。

发送确认排队请求后、已成功或结果不明时禁止直接继续新一轮下单。异常响应只记录状态码、类型、重定向情况和长度，不记录正文或凭据。停止只取消后续客户端操作，不会撤销服务端已生成的订单。

## 停止、日志与数据

`runtime.py` 提供取消令牌和事件。请求之间检查取消，网络请求仍需等待自身超时。安全停止后的继续操作从原配置重新创建任务，计数归零；原停止时间过期时需要修改，不滚到次日。

日志由 `logging_utils.py` 脱敏、`gui/async_logging.py` 异步写入并批量显示。日志文本不驱动任务状态。GUI 不持久化登录凭据；用户主动保存的 JSON 包含配置姓名和行程。运行缓存与日志不是源码的一部分。

测试使用模拟接口；本地回归通过不保证 12306 实时网页接口始终不变。安装、测试、构建方法见 [开发指南](开发指南.md)。
